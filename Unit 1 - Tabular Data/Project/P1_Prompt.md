## Notebook 2 — Preprocessing
*Filename: `P1_CarSales-2_Preprocessing_<TeamName>.ipynb`*

Build a clean, model-ready dataset. **EVERY** decision **MUST** have a markdown explanation. Read in the raw data at the top of this notebook. Do not carry over objects from the EDA notebook.

> **Label leakage warning:** `price` is your regression target. No engineered feature may use `price` or any column that directly encodes price information. Treat `price` as off-limits for feature engineering — it exists in the dataset solely to define the target variable.

Your preprocessing **MUST** address:

- **Dropping**
    - Columns that are genuinely useless, rows that cannot be salvaged — justify each
- **Data types**
    - Some columns have mixed data types — normalize these to a single data type
- **Outlier handling**
    - Handle `year`, `price`, and `mileage` at minimum
    - Justify your method and thresholds
    - **MUST NOT** drop more than 50% of rows — confirm this with code
- **Imputation**
    - Strategy should depend on the column and what makes domain sense
    - There are many places where you can be more clever than simple median/mode/unknown filling
- **Feature engineering**
    - Derive as many informative features as you can from what's available
    - Some columns (e.g., `major_options` and `listed_date`) require careful parsing before they can be used — figure out how
    - **No engineered feature may use `price` or any column that is a direct function of price**
    - After the progress report, **every team is required to implement every feature any other team presented**, plus any additional ones the instructor specifies. This is not extra credit and it is not optional — you will be asked about it at the next progress report
- **Encoding**
    - Label-encode binary columns
    - One-hot encode nominal columns with the reference category dropped
    - For each nominal column, drop the most frequent category as the reference and retain dummies for only the next 20 most frequent remaining categories — additional categories beyond 20 should be dropped
- **Scaling**
    - Standard-scale all non-metadata features **except `price`**, which must remain in its original form
- **Preserving subgroup metadata**
    - Retain the original object-dtype version of every categorical column that gets encoded (e.g., keep original `make` alongside its dummies `make_Toyota`, `make_Honda`, etc.)
    - These columns will be used for the fairness audit in Notebook 5; they must be present in all exported datasets but must be excluded when constructing `X` and `y` for any modeling step
- **Export**
    - Perform a train/test split
    - Save the two splits to your local class data folder as `processed_train.csv` and `processed_test.csv`

You will be graded on the breadth and quality of your **first-pass** feature engineering — the features your team comes up with *before* the progress report. Adopting other teams' ideas afterward is mandatory but earns nothing; the credit is for what you brought. Try to be comprehensive on the first pass.

### How this notebook is scored

**Coverage checklist**
- Column and row drops, each justified
- Mixed dtypes normalized to a single type
- Outliers on `year`, `price`, and `mileage` with justified thresholds; under 50% of rows dropped, **confirmed in code**
- Imputation strategy chosen per column, not globally
- Feature engineering, including `major_options` and `listed_date` parsing
- Encoding: binary label-encoded; nominal one-hot with reference category dropped and the top-20 rule applied
- Scaling applied to all non-metadata features except `price`
- Object-dtype metadata columns preserved for Notebook 5
- Split performed; `processed_train.csv` and `processed_test.csv` exported
