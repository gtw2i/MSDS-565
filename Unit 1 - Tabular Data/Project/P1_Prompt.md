## Notebook 2 — Preprocessing
*Filename: `P1_CarSales-2_Preprocessing_<TeamName>.ipynb`*

Build a clean, model-ready dataset amd export it for later use.

> **EVERY** decision **MUST** have a markdown explanation. Read in the raw data at the top of this notebook. Do not carry over objects from the EDA notebook.

> **Label leakage warning:** `price` is your regression target. No engineered feature may use `price` or any column that directly encodes price information. Treat `price` as off-limits for feature engineering.

Your preprocessing **MUST** address:

1. **Dropping**
    - Columns that are genuinely useless, rows that cannot be salvaged — justify each
2. **Data types**
    - Some columns have mixed data types — normalize these to a single data type
3. **Outlier handling**
    - Handle `year`, `price`, and `mileage` at minimum
    - Null and outlier dropping **MUST NOT** drop more than a combined 50% of rows — confirm this with code
4. **Imputation**
    - Strategy should depend on the column and what makes domain sense
    - There are many places where you can be more clever than simple median/mode/unknown filling. Points will be lost for simplistic imputation where better methods were available.
5. **Feature engineering**
    - Derive as many informative features as you can from what's available
    - Some columns (e.g., `major_options` and `listed_date`) require careful parsing before they can be used — figure out how
    - **No engineered feature may use `price` or any column that is a direct function of price**
    - After the progress report, **every team is required to implement every feature any other team presented**, plus any additional ones the instructor specifies. This is not extra credit and it is not optional — you will be asked about it at the next progress report
6. **Encoding**
    - Label-encode binary columns
    - One-hot encode categorical columns. For each, drop the most frequent category as the reference and retain dummies for only the top 20 most frequent remaining categories — additional categories beyond 20 should be dropped. There are some columns that would produce thousands of dummies if this precaution isn't taken.
7. **Preserving subgroup metadata**
    - Retain the original object-dtype version of every categorical column that gets encoded (e.g., keep original `make` alongside its dummies `make_Toyota`, `make_Honda`, etc.)
    - These columns will be used for the fairness audit in Notebook 5. They must be present in all exported datasets but must be excluded when constructing `X` and `y` for any modeling step
8. **Scaling**
    - Standard-scale all non-metadata features **except `price`**, which must remain in its original form
9. **Split and export**
    - Split the data 80/20 using `random_state=42`, and save the split to your local class data folder as `processed_train.csv` and `processed_test.csv` — Notebook 3 will reuse this exact split

## Notebook 3 — Modeling
*Filename: `P1_CarSales-3_Modeling_<TeamName>.ipynb`*

Train, evaluate, and compare regressors on your preprocessed dataset.

> If your R² is suspiciously close to 1, you have likely leaked `price` information into a feature — double check your Notebook 2 feature engineering.

Your submission **MUST** include:

    - **Defining the target variable:** Use `price` as your regression target (`y`). Drop `price` and all object-dtype metadata columns before constructing `X`. Apply the same column drops to both train and test.
2. **Models**
    - **sklearn**
        - Train **AT LEAST 3** different regressor types; **Linear Regression and Random Forest must be in the list**

        - Train **AT LEAST 3** different keras networks with differing architectures

## Notebook 4 — Feature Selection
*Filename: `P1_CarSales-4_FeatureSelection_<TeamName>.ipynb`*

Use Random Forest importance and VIF filtering to trim the feature set, then compare model performance before and after.

Steps **MUST** be completed in this order:

1. **Setup**
    - Read in `processed_train.csv` and `processed_test.csv` — Notebook 2's split — and construct `X_train`, `y_train`, `X_test`, `y_test` the same way Notebook 3 did
    - Read in Notebook 3's `model_metrics.csv` for baseline performance reference — you do **not** need to reload the saved models
    - Use clear markdown section headers to delineate each step
2. **Importance-based filtering**
    - Fit a Random Forest on `X_train` and rank features by importance — retain the top 100 features
3. **VIF filtering**
    - Apply VIF to the importance-reduced set and **iteratively** drop any feature with VIF > 10
4. **Retrain on the selected feature set**
    - Retrain every sklearn model type from Notebook 3 on the reduced `X_train` using the same parameter grids — cross-validate on training folds, then let `GridSearchCV` refit `best_estimator_` on the whole (reduced) training set
    - Retrain every keras architecture from Notebook 3 on the reduced `X_train` — cross-validate on training folds, then refit one final version on the whole (reduced) training set to export
5. **Before/after comparison**
    - Evaluate each retrained model's CV performance (training folds) and its held-out performance on the reduced `X_test`/`y_test`, and build a performance table in the exact same shape as Notebook 3's `model_metrics.csv`
    - Compare it row-by-row against Notebook 3's `model_metrics.csv` — which models improved, which got worse, and by how much?
    - Feature selection buys speed as well as (or instead of) accuracy — how much of each did it buy you here?
    - Document what changed, what didn't, and why
6. **Export**
    - Apply the selected feature set to both splits and save as `selected_train.csv` and `selected_test.csv` in your local class data folder
    - Include the `price` and all object-dtype metadata columns in these files
    - Save your after-selection performance table to your local class data folder as `model_metrics_selected.csv`
